# CostBuddy 电脑端响应式适配设计

## 背景

CostBuddy 当前以三栏工作台为核心：左侧录入交易参数，中间展示核心测算结果，右侧展示目标反推、方案矩阵和资金明细。该结构在标准桌面宽度下有效，但现有断点没有覆盖常见笔记本开启系统缩放后的实际 CSS 视口。

已在真实页面中稳定复现：当视口处于 `821-1199px` 时，左侧栏宽约 `282px`，`.controls-header` 仍使用单行 flex 布局。标题组需要约 `160px`，工具组需要约 `128px`，加上间距后超过容器宽度，因此“ORDER TICKET / 交易参数”和“保存、费用、清除”发生压缩、截断或重叠。到 `1200px` 时才启用上下两行布局。

`1093x700` 是重点复现尺寸，它近似对应 `1366x768` 屏幕在 125% 系统缩放下的可用 CSS 视口。

## 目标

- 在常见笔记本、标准桌面、2K 和 4K 屏幕上保持完整、清晰且可操作的页面。
- 宽度允许时保留参数与结果同时可见的桌面工作台优势。
- 空间不足时优先重排局部模块，不通过持续缩小字体来维持三栏。
- 当视口不足以满足三栏最小宽度时，切换为单栏或分步布局，禁止横向溢出。
- 低高度窗口允许内容自然滚动，避免卡片被压扁、文字重叠或按钮不可点击。
- 日间和夜间模式使用相同的布局行为。

## 非目标

- 不修改成本计算公式、费用计算、持仓簿、方案保存、分享或备份逻辑。
- 不重新设计品牌、配色、文案或信息架构。
- 不引入框架、构建工具或第三方响应式库。
- 不要求所有电脑尺寸都严格保持“一屏展示”；可读性和操作完整性优先。

## 响应式分层

### 1. 窄窗口：小于 1000px

- 不强行维持三栏工作台。
- 使用现有单栏/分步页面模式展示交易参数与测算结果。
- 页面和主要面板不得产生横向滚动。
- 主要输入、数字和操作按钮必须保持完整可见。

### 2. 紧凑桌面：1000-1199px

- 保留左侧交易参数、中间核心结果、右侧辅助结果三栏结构。
- `.controls-header` 改为上下两行：第一行显示 “ORDER TICKET / 交易参数”，第二行显示保存、费用和清除操作。
- 工具按钮在第二行按可用宽度分配，不与标题争抢空间。
- 顶部全局操作、结果卡片标题和表格按信息优先级收缩；主要命令、金额和输入值不得截断。
- 修正当前约 `1024px` 附近的轻微横向溢出。

### 3. 标准桌面：1200-2199px

- 保持舒展的三栏工作台。
- 使用现有标准桌面输入重排，并统一栏宽、间距和最小尺寸约束。
- 不因窗口继续增宽而无限拉长文本或表格。

### 4. 超宽与 4K：2200px 及以上

- 页面居中并限制内容最大宽度。
- 适当放大控件、字号、间距和点击目标。
- 保持数据区聚焦，避免重要数据横跨过长距离。

## 高度策略

- `700px` 及以下视为低高度电脑窗口。
- 保留清晰的字号和控件高度，减少非关键留白。
- 当内容超过可用高度时，允许页面或明确的工作区自然滚动。
- 禁止通过负间距、内容遮盖或过度缩小字号维持一屏布局。
- 弹窗高度不得超过视口；内容区可滚动，关闭按钮始终可访问。

## 模块行为

### 交易参数栏

- 标题区和工具区在紧凑桌面中分行。
- 保存、费用、清除均保留明确的可点击区域和工具提示/可访问名称。
- 输入框单位、数字和字段标题不得相互覆盖。
- 港股和美股切换后的字段变化不能引起栏宽跳动或横向溢出。

### 顶部栏

- 品牌、免责声明和全局工具按优先级分配空间。
- 空间不足时可隐藏次要说明或仅保留图标，但不得隐藏主要命令。
- 顶部栏不得推动工作台产生横向滚动。

### 结果区

- 回本成本、资金变化等主要数字优先完整显示。
- 次要摘要允许省略号，但完整中文模块标题应优先保留。
- 方案矩阵的列宽需保证金额与操作按钮可辨认、可点击。
- 图表和阶段卡片随容器缩放，不得超出面板边界。

### 弹窗

- 费用设置、持仓簿、方案、支持/反馈和数据导入导出弹窗均需在电脑端视口内可用。
- 窄窗口和低高度窗口中，弹窗主体允许纵向滚动。
- 弹窗操作区和关闭入口不能被内容挤出可视区域。

## CSS 实现原则

- 在 `styles.css` 末尾增加一个集中、可追踪的响应式修正层，覆盖历史规则，避免大范围重写现有 5000 多行样式。
- 统一使用 `min-width: 0`、`minmax(0, 1fr)`、明确的 grid 行列和必要的 `overflow` 约束。
- 断点以页面实际可用宽度为准，不依赖设备型号。
- 不使用随视口宽度连续缩放的正文基础字号；仅在已有的大数字展示中保留受限的 `clamp()`。
- 不使用负字距解决容纳问题。
- 日间和夜间模式共享布局规则，主题规则只处理颜色。

## 验收视口

必须验证以下视口：

- `1024x768`
- `1093x700`
- `1280x720`
- `1366x768`
- `1440x900`
- `1600x900`
- `1920x1080`
- `2560x1440`
- `3840x2160`

每个视口至少检查：

- 页面无非预期横向滚动。
- 标题、按钮、输入框、单位、金额和表格内容没有重叠。
- 交易参数标题区在紧凑桌面中正确分为两行。
- 主要按钮可见、可点击，文字不会溢出按钮边界。
- 主要计算输入与输出仍能正常更新。
- 日间和夜间模式布局一致。
- 弹窗在当前视口内可关闭、可滚动、可操作。

## 自动化与视觉验证

- 增加独立的响应式布局检查脚本，读取真实页面并对关键元素矩形进行断言。
- 在修改 CSS 前先让检查在已知问题视口失败，确认测试能够捕获标题与工具组的冲突以及页面横向溢出。
- 修改后重复运行相同检查，确认所有目标视口通过。
- 使用浏览器截图检查桌面、紧凑桌面和 4K 三类代表尺寸；同时检查日间与夜间模式。
- 运行 JavaScript 语法检查，确保样式改动没有伴随脚本回归。

## 完成标准

- 所有目标视口的自动化布局检查通过。
- 浏览器截图未发现元素重叠、截断、异常留白或无意义拉伸。
- 核心计算交互和弹窗操作通过抽样验证。
- 改动提交到 `codex/desktop-responsive` 并推送到 GitHub。
- 不直接合并到 `main`，因此不会触发生产部署。

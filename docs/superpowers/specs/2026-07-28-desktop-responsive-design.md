# CostBuddy 电脑端三列响应式优化设计

## 状态

- 设计方向：已确认
- 桌面结构：保留原有三列工作台
- 视觉方向：A「精致金融工具」为主体，吸收 B「专业交易终端」的数据表达
- 实现分支：`codex/desktop-responsive`
- 合并与部署：本轮只推送功能分支，不合并 `main`，不触发生产部署

## 背景

CostBuddy 当前使用三列工作台：左侧录入交易参数，中间展示核心测算结果，右侧展示目标反推、方案矩阵和资金明细。这个结构符合产品的主要操作路径，用户明确要求继续保留，不改成两栏工作台。

第一轮响应式调整解决了横向溢出、低高度滚动和弹窗可达性，自动化检查也能证明页面没有重叠。然而真实页面在普通笔记本宽度下仍然显得拥挤。实测列宽如下：

| 视口宽度 | 左侧参数 | 中间结果 | 右侧辅助 |
|---|---:|---:|---:|
| 1024px | 272px | 407px | 275px |
| 1093px | 276px | 445px | 300px |
| 1280px | 346px | 523px | 323px |
| 1366px | 358px | 569px | 351px |
| 1440px | 358px | 615px | 379px |
| 1600px | 358px | 714px | 440px |

问题不再是单纯的技术溢出，而是三列在不足宽度下仍被强行保留。标题、按钮、数据和表格虽然能够放进容器，却没有形成舒适、明确的阅读顺序。

## 目标

- 保留 CostBuddy 原有三列工作台，不改变主要功能归属。
- 让普通笔记本上的三列拥有明确的输入、理解和决策动线。
- 使用 A 风格建立成熟、友好、可信的金融工具界面。
- 使用 B 风格增强金额、盈亏、表格和状态的识别效率。
- 空间不足时使用现有分页模式，禁止为了维持三列而持续缩字或压缩控件。
- 低高度窗口允许自然纵向滚动，不要求所有电脑严格一屏展示。
- 日间和夜间模式使用相同结构、顺序和断点。

## 非目标

- 不修改成本公式、费用计算、图表数据、持仓簿、方案保存、分享或备份逻辑。
- 不改成两栏工作台，也不把右侧辅助模块移动到中间结果下方。
- 不把产品整体改成暗色交易终端，不大量使用英文大写或等宽字体。
- 不引入框架、构建工具或第三方响应式组件库。
- 不进行与电脑适配无关的功能重构。

## 核心设计

### 三列职责

桌面工作台始终遵循一个从左到右的完整流程：

1. 左列负责输入交易计划。
2. 中列负责解释计算结果。
3. 右列负责辅助决策和核对明细。

三列之间使用安静的结构分隔，不增加夸张箭头、步骤说明或教学文案。用户通过标题、层级和模块顺序自然理解流程。

### 左列：交易输入

模块顺序保持现有逻辑：

1. 交易参数标题和操作区。
2. 持仓基准。
3. 买入计划。
4. 卖出计划。

标题与工具必须分为上下两行。“保存当前”“费用”“清除”使用等宽三列工具区，不与 “ORDER TICKET / 交易参数”争抢同一行。

持仓、买入和卖出继续使用现有颜色含义：蓝色表示主要输入与买入，橙色表示卖出。颜色只用于细色条、状态和控件反馈，不给整个模块铺大面积彩色背景。

### 中列：理解结果

模块顺序固定为：

1. 资金回本成本和本次净现金流。
2. 交易后持仓、需收回总成本、总体盈亏和回本距离。
3. 回本成本演变。
4. 买入价与回本成本曲线。

回本成本是页面唯一的超大数字。净现金流保持明显但次一级的视觉权重。四个摘要使用统一的数据条，不再形成四个彼此竞争的重卡片。

成本演变按 “交易前 → 卖出后 → 买入后” 横向排列，当前最终状态使用蓝色强调。市场曲线获得中列剩余的主要空间，不被右列侵占，也不为强行一屏展示而降低到难以阅读的高度。

### 右列：采取行动

右列顺序由当前实现调整为：

1. 目前股价与回本价。
2. 目标成本反推。
3. 1 至 5 手买入方案。
4. 资金明细。

这个顺序先回答“目前在哪里”，再回答“目标是多少和需要买多少”，随后比较不同方案，最后核对资金计算细节。

股价位置模块保持紧凑并置顶。目标反推保留输入与主要应用按钮。方案矩阵获得右列最多的纵向空间。资金明细位于最后，作为核对信息而不是首要结论。

## 视觉语言

### A：整体体验

- 保留 CostBuddy 的浅色背景、蓝色主色、绿色正向状态、红色负向状态和橙色卖出标识。
- 使用柔和但清晰的中性色边界，减少重复描边和卡片堆叠感。
- 面板圆角保持克制，桌面数据面板不超过现有设计体系需要的范围。
- 中文模块标题是主要层级；英文小标题只作辅助，降低尺寸和对比度。
- 通过留白、分隔线和标题层级组织内容，不依靠装饰背景、渐变、阴影或大面积单色填充。
- 顶部栏、参数区和结果区保持成熟金融工具的可信感，不做营销页面或行情大屏。

### B：数据表达

- 金额、股数、百分比和价格使用等宽数字特性 `font-variant-numeric: tabular-nums`，不把所有正文改成等宽字体。
- 正向净现金流使用绿色，负向盈亏使用红色；状态不能只靠颜色，还要保留正负号和明确文案。
- 方案矩阵使用清楚的横向分隔、数字对齐和稳定列宽，减少金额在列内跳动。
- 主要金额不得省略或截断。空间不足时优先让标签换行或切换布局。
- 夜间模式可以借鉴交易终端的高对比结构，但仍保留中文标题、适当留白和 CostBuddy 品牌。

### 明确排除

- 不使用黑色终端顶部栏作为日间模式主视觉。
- 不大量使用全大写英文、密集网格线或命令行式控件。
- 不用持续缩小字体、负字距或内容裁切解决宽度不足。
- 不给每个数据块增加独立阴影、厚边框或不同颜色。

## 响应式分层

### 1. 窄电脑窗口：小于 1200px

- 不显示三列工作台，使用现有“交易参数 / 测算结果”分页模式。
- 结果页内部按中列结果优先、右列辅助随后进行纵向排列。
- 页面和主要面板不得产生横向滚动。
- 输入、金额、表格和操作按钮保持完整可见。
- 该层覆盖 `1024px`、`1093px` 等无法为三列提供最低舒适宽度的电脑窗口。

### 2. 紧凑三列桌面：1200-1439px

- 使用原有三列工作台。
- 左列保持约 `294-322px`，中列优先获得剩余宽度，右列保持约 `286-322px`。
- `1200px` 下中列不得低于约 `500px`，从 `1280px` 起不得低于约 `520px`；如果无法满足，则回退到分页模式。
- 参数标题与工具固定分行。
- 顶部栏隐藏或缩短次要说明，主要命令保持可用。
- 页面允许纵向滚动，禁止通过压缩字号维持一屏。

### 3. 标准三列桌面：1440-2199px

- 左右列可以逐步增加到约 `330-380px`，中列继续获得主要增量空间。
- 保持三列职责和右列新顺序不变。
- 限制文本行长和方案表格列宽，避免宽屏下无意义拉伸。

### 4. 超宽与 4K：2200px 及以上

- 页面居中并限制最大工作区宽度。
- 按比例增加控件高度、字号和模块间距，但不改变三列动线。
- 主要数据保持聚焦，避免信息横跨过长距离。

## 高度策略

- `700px` 及以下视为低高度电脑窗口。
- 页面允许自然纵向滚动，三列不要求在一个视口高度内结束。
- 保持输入框、按钮和正文的正常可读尺寸，只压缩非关键留白。
- 禁止使用负间距、内容遮盖或极小字体维持一屏。
- 弹窗高度不得超过视口；弹窗主体可滚动，标题、关闭入口和底部操作始终可访问。

## 顶部栏

- 品牌位于左侧，全局工具位于右侧，免责声明和隐私说明占用中间弹性空间。
- 紧凑三列桌面优先缩短或隐藏次要说明，不压缩品牌和主要命令。
- 次要命令可只保留熟悉图标并提供可访问名称和悬停提示。
- 顶部栏不得引起页面横向滚动，也不得把工作台首行向下挤成异常高度。

## 交互与数据

- 所有现有输入、计算、保存、应用方案、分享、主题切换和弹窗行为保持不变。
- 右列模块移动只改变 DOM 或 CSS 展示顺序，不改变事件绑定和数据来源。
- 日间和夜间模式切换不能改变列宽、模块顺序或滚动位置策略。
- 港股和美股切换后的字段变化不能引起栏宽跳动或横向溢出。
- 图表尺寸跟随中列容器变化，并在重新布局后正确重绘。

## CSS 与结构实现原则

- 优先使用现有 HTML、CSS 变量和组件类，不引入新的视觉框架。
- 将本轮桌面响应式规则集中在 `styles.css` 末尾的单一覆盖层，减少历史媒体查询互相争抢。
- 使用明确的 CSS Grid 列宽、`minmax(0, 1fr)`、`min-width: 0` 和必要的溢出约束。
- 若右列顺序仅靠 CSS `order` 会造成键盘导航与视觉顺序不一致，则在 `index.html` 中同步调整 DOM 顺序。
- 不使用随视口宽度连续缩放的正文基础字号；超大结果数字可以使用受限的 `clamp()`。
- 不使用负字距解决文字容纳问题。
- 日间和夜间共享布局规则，主题规则只处理颜色和对比度。

## 验收视口

必须验证以下视口：

- `1024x768`：分页模式
- `1093x700`：分页模式与低高度滚动
- `1200x800`：紧凑三列下限
- `1280x720`：重点普通笔记本三列
- `1366x768`：常见笔记本三列
- `1440x900`：标准三列
- `1600x900`
- `1920x1080`
- `2560x1440`
- `3840x2160`

每个代表视口至少检查：

- 页面无非预期横向滚动。
- 标题、按钮、输入、单位、金额和表格没有重叠或裁切。
- 小于 `1200px` 时分页入口可见，三列不显示。
- 大于等于 `1200px` 时三列同时可见；中列在 `1200px` 下至少约 `500px`，从 `1280px` 起至少约 `520px`。
- 参数标题和工具在三列模式中保持上下两行。
- 右列顺序为股价位置、目标反推、方案矩阵、资金明细。
- 主要数字和方案矩阵使用稳定数字对齐。
- 低高度窗口可自然滚动。
- 日间和夜间布局一致，文本对比度清楚。
- 主要弹窗可关闭、可滚动、可操作。

## 自动化与视觉验证

- 先更新响应式测试，让旧实现因断点、三列最小宽度和右列顺序不符合新规格而失败。
- 几何测试必须验证分页/三列模式、三列最小宽度、标题与工具分行、页面溢出和模块顺序。
- 使用真实 Chrome 对 `1093x700`、`1280x720`、`1440x900` 和 `3840x2160` 生成日间与夜间截图。
- 自动化通过后仍必须人工检查截图，因为“不重叠”不能证明视觉舒适。
- 抽样验证计算输入更新、目标方案应用、主题切换和主要弹窗。
- 运行 JavaScript 语法检查，确保 DOM 调整没有引入脚本回归。

## 完成标准

- 所有目标视口的自动化布局检查通过。
- `1280x720` 和 `1366x768` 的三列页面保持原结构，同时中列和右列可清楚阅读。
- 小于 `1200px` 的窗口不再硬塞三列。
- 页面整体采用 A 风格，金额和表格采用 B 风格的数据表达。
- 右列决策动线符合本规格，键盘导航顺序与视觉顺序一致。
- 浏览器截图未发现重叠、裁切、异常留白、过度密集或无意义拉伸。
- 核心计算交互和弹窗操作通过抽样验证。
- 改动提交并推送到 `codex/desktop-responsive`。
- 不直接合并到 `main`，不创建生产部署。
